# Study C (paper: "Study 2"): canonicalization versus augmentation

Design: `paper1/SPEC.md` section 2. Results are in the paper's section "Study 2" and Tables `tab:study2` / `tab:study2-obf`, generated by `paper1/paper/make_assets.py`.

| File | Role |
|---|---|
| `train_arm.py` | retrains GuardShield (DeBERTa-v3-small) with the shipped two-stage recipe for one arm and seed |
| `run_study_c.py` | driver: `setup`, `train`, `guards`, `score`, `metrics`, `pack`, `unpack` |
| `guards_study_c.json` | generated: the 51 Study C guards (21 retrained checkpoints and their inference-time arms) |
| `analyze.py` | per-arm mean ± std at 90% clean TPR, seen vs held-out families; writes `study_c_summary*.json` |
| `hindi_joiners.py` | Devanagari joiners deleted by each canonicalizer in the Aya Dataset's Hindi prompts |

Run directories `paper1/runs/study_c_obf` (Gandalf × Dolly, secondary) and `paper1/runs/study_c_pids` (PIDS-Bench, primary) hold the same datasets as `obf_main` and `pids_main`, so Study A's `metrics.json` keeps its 18 guards. Per-item scores are committed as `scores.zip` (LZMA, about 3 MB for both runs); restore them before re-running `metrics` or `analyze.py`:

```bash
python paper1/study_c/run_study_c.py unpack
```

The 21 retrained checkpoints (`models/study_c/`, about 0.5 GB each) are not committed. `python paper1/study_c/run_study_c.py train` rebuilds them (about 6 hours on an RTX 3050 laptop GPU; each `training_summary.json` records seed, data sizes and validation metrics).

Results (2026-10-16), PIDS-Bench, GuardShield, mean over five seeds: seen character families AUROC 0.55 (retrained baseline), 0.84 (script-aware canonicalizer), 0.62 (benign-twin augmentation), 0.87 (both). On the Gandalf pairs augmentation matches canonicalization (0.85 vs 0.86, also after removing the 158 pairs that overlap GuardShield's training data). Augmentation lowers default-threshold recall and benign FPR together (94% → 45% and 94% → 29%).
